# 客服服务规范与人工升级

## 1. 文档适用范围

本文定义客服 Agent 和人工客服的统一服务边界，包括信息收集、回复结构、风险识别、升级人工、投诉处理、补偿边界、重复联系、跨部门协作以及不应承诺的事项。

## 2. 基本回复原则

一个高质量客服回复应尽量包含：

1. 对用户问题的明确判断；
2. 当前状态或原因；
3. 下一步可执行操作；
4. 预计时效或范围；
5. 需要用户补充的信息；
6. 如果无法解决，明确升级路径。

避免：

- 只说“请耐心等待”；
- 重复用户原话但不给方案；
- 过度承诺；
- 编造系统中不存在的状态；
- 把内部错误码直接丢给普通用户而不解释。

## 3. 信息收集

尽量一次性收集解决问题所需字段。

订单类：

- order_id
- 商品
- 时间
- 当前状态

支付类：

- payment_id
- 金额
- 支付渠道
- 时间

技术类：

- request_id
- 错误码
- 客户端版本
- 复现步骤

禁止索取不必要的密码、验证码、完整银行卡信息等。

## 4. 先判断风险，再执行普通 SOP

高风险场景：

- 未经授权支付；
- 账户被盗；
- 数据泄露；
- 人身或产品安全风险；
- 高金额争议；
- 用户明确法律、监管或媒体投诉；
- 大面积系统故障。

这些场景优先级高于普通退款、物流等脚本。

## 5. 什么时候升级人工

以下情况应考虑人工升级：

- 当前 Agent 缺少必要权限；
- 需要读取受限后台信息；
- 需要跨部门人工确认；
- 用户连续两轮明确表示自动回答没有解决问题；
- 业务规则存在例外；
- 需要补偿、退款或特殊审批；
- 风险级别较高；
- 用户明确要求人工且问题无法通过自助完成。

“转人工”本身不能等于结束对话。升级前应整理已有信息，避免人工再次从头询问。

## 6. 升级工单内容

一张好的升级工单应包含：

- 用户核心诉求；
- 相关 order_id / payment_id / request_id；
- 已完成的排查；
- 当前系统状态；
- 已知证据；
- 风险等级；
- 用户期望；
- 建议下一步。

不应只写：“用户很生气，请处理。”

## 7. 投诉处理

用户表达不满时，应区分：

- 普通体验抱怨；
- 正式服务投诉；
- 要求主管介入；
- 要求监管/法律处理；
- 涉及安全或财产损失。

客服可以承认服务体验问题，但不要在事实尚未核查时承认法律责任或承诺赔偿金额。

## 8. 重复联系

同一问题多次联系时：

1. 关联历史会话和工单；
2. 说明当前进度；
3. 不重复要求用户提供已经有效提交的信息；
4. 若已经超过承诺时效，提升优先级；
5. 记录前次处理失败原因。

这是记忆系统和工单系统需要协同的典型场景。

## 9. 补偿边界

客服补偿可以包括：

- 积分；
- 优惠券；
- 运费补偿；
- 低金额服务补偿。

补偿应有原因、金额和权限限制。

不允许：

- 用补偿替代必要的退款；
- 为结束对话无限发券；
- 对高风险争议私自承诺现金赔偿；
- 绕过审批上限。

## 10. 时效表达

推荐：

- “预计 1-3 个工作日完成审核。”
- “目前仍在银行正常处理时效内。”
- “我们会升级物流调查，完成后更新结果。”

不推荐：

- “今天肯定到账。”
- “下午三点前一定送到。”
- “肯定不会再出问题。”

如果没有可靠的精确 ETA，就给范围而不是虚构具体时间。

## 11. 没有答案时怎么处理

当知识库没有依据：

1. 明确说明当前无法从已知信息确认；
2. 不编造规则；
3. 提供可验证的下一步；
4. 必要时升级。

例如用户问公司内部未公开的风控阈值，正确做法不是猜，而是解释无法披露具体规则。

## 12. 多问题拆解

用户可能一次问：

“订单三天没更新，而且信用卡扣了两次，我还想改地址。”

应拆成：

- 物流异常；
- 重复扣款；
- 地址修改。

不同模块可以并行处理，但最终回复要合并成清晰的行动项，而不是把多个 Agent 的原始输出直接堆在一起。

## 13. 客服语气

推荐语气：

- 明确；
- 简洁；
- 不推诿；
- 不过度热情；
- 说明限制；
- 给可执行步骤。

避免模板化道歉反复出现。真正重要的是解决路径。

## 14. 对内部系统的描述边界

用户通常不需要知道：

- 路由权重；
- 风控模型阈值；
- 内部数据库结构；
- 监控指标细节；
- Agent prompt；
- 安全检测绕过方法。

客服可以解释结果和流程，但不泄露可能降低系统安全性的内部实现。

## 15. 人工升级优先级

示例：

### P0 紧急
- 数据泄露；
- 账户大规模被盗；
- 严重安全事故；
- 大面积支付错误；
- 可能造成人身风险。

### P1 高
- 高金额未经授权交易；
- 高价值商品丢失；
- 用户连续多次售后失败；
- 关键功能大面积不可用。

### P2 普通
- 单个订单异常；
- 普通退款超时；
- 发票修改；
- 会员权益异常。

## 16. 关闭工单条件

工单可以关闭前应确认：

- 用户核心诉求已解决；
- 或已明确转交负责团队；
- 用户已获得必要编号和后续方式；
- 不存在仍未处理的高风险事项。

不能因为用户暂时没有回复就立即把高风险工单当作已解决。

## 17. 客服与 Agent 协作

Agent 可以负责：

- 意图识别；
- 知识检索；
- 常规规则解释；
- 信息收集；
- 初步排查；
- 工单摘要。

人工更适合：

- 高风险判断；
- 特殊审批；
- 复杂争议；
- 情绪高度升级；
- 跨部门协调；
- 需要真实业务权限的操作。

## 18. 评测注意事项

客服回答质量不能只看“是否说得像人”。

至少评估：

- 答案是否与知识库一致；
- 是否遗漏关键条件；
- 是否引用了错误政策；
- 是否在无依据时编造；
- 是否要求不必要敏感信息；
- 是否给出正确升级路径。

## 19. 常见问题

### 用户一说“转人工”就必须马上转吗？
如果系统支持，应尊重明确的人工诉求；同时可以先整理上下文，减少人工重复询问。

### 没查到规则可以凭经验回答吗？
不建议。应明确不确定，并进入核实或升级流程。

### 用户很生气，可以直接承诺赔偿吗？
不能。可以表达理解并升级，但赔偿需要符合权限和审批规则。
