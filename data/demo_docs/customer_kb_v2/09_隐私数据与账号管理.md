# 隐私数据与账号管理

## 1. 文档适用范围

本文覆盖个人资料修改、隐私信息、数据导出、账户注销、客服可见数据范围、数据保留、安全删除以及敏感信息处理边界。

## 2. 个人资料

用户可以维护：

- 昵称；
- 头像；
- 收货地址；
- 联系邮箱；
- 手机号；
- 常用偏好。

手机号、邮箱等同时承担身份验证功能时，修改需要额外验证。

## 3. 敏感信息分类

客服场景中的敏感信息包括但不限于：

- 登录密码；
- 短信验证码；
- TOTP；
- 完整银行卡号；
- CVV；
- 身份证件完整号码；
- API Secret；
- 私钥。

客服不应主动索取这些信息。

## 4. 最小必要原则

处理问题只收集解决该问题所需的信息。

例如：

- 查询订单需要订单号，不需要银行卡 CVV；
- 技术故障需要 request_id，不需要完整 API Secret；
- 登录问题需要账户标识，不需要用户把密码发来。

## 5. 数据导出

用户可以申请导出与其账户相关的数据。出于安全考虑，导出属于敏感操作，通常需要再次验证身份。

导出内容可包括：

- 账户基本信息；
- 订单记录；
- 售后记录；
- 会员和积分记录；
- 可导出的偏好设置。

部分内部安全日志、反欺诈特征或受限制信息不一定对外导出。

## 6. 账户注销

注销前应明确：

- 账户是否有未完成订单；
- 是否有进行中的退款或售后；
- 是否有未结清订阅；
- 是否存在争议交易；
- 是否需要先完成身份验证。

存在进行中业务时，可要求先处理完相关事项再进入注销。

## 7. 注销后的影响

注销后可能发生：

- 无法继续登录；
- 会员权益失效；
- 积分无法继续使用；
- 已完成订单的必要记录按法定或业务要求继续保留；
- 部分匿名化统计数据可能不再与用户身份关联。

“注销账户”不应被解释为“所有服务器备份立即物理清零”。

## 8. 数据删除请求

数据删除需要区分：

- 用户可自行删除的资料；
- 可在注销时删除的数据；
- 因财务、交易、安全或合规原因需要保留的数据。

客服如果不确定保留期限，应升级隐私或合规团队，不要随意承诺“马上全部删除”。

## 9. 客服访问权限

客服系统应遵循最小权限原则。不同角色只能查看其业务所需字段。

例如普通客服可能看到：

- 订单；
- 售后状态；
- 用户联系方式的脱敏信息。

但不应看到：

- 完整支付卡片；
- 用户密码；
- 风控模型详细特征；
- 不相关业务数据。

## 10. 截图和附件

用户上传截图时可能包含：

- 身份证号；
- 银行卡号；
- 地址；
- 他人聊天记录；
- 邮箱和手机号。

客服应提醒用户遮挡无关敏感信息，并只保留解决问题必要的附件。

## 11. 数据泄露或疑似泄露

如果用户报告：

- 收到不属于自己的订单信息；
- 看到了他人账户内容；
- 个人信息被错误发送；
- API 返回了其他租户数据；

应立即升级安全与隐私事件，不要按普通客服问题处理。

## 12. 第三方服务

物流、支付、邮件、短信等功能可能依赖第三方。平台只应向第三方发送实现服务所需的数据，并受相应数据处理协议或权限控制。

客服回答时不需要暴露内部供应商架构，除非对解决问题有必要。

## 13. 账号合并

若产品支持账号合并，需要确认：

- 两个账户都属于同一用户；
- 订单和会员资产是否可迁移；
- 第三方登录绑定冲突；
- 手机号/邮箱唯一性。

不应因为用户仅知道两个邮箱就直接合并账户。

## 14. 客服处理 SOP

### 用户要求“把我的所有数据删掉”
先判断是删除某项资料、注销账户还是正式的数据删除请求。

### 用户发来了银行卡截图
提醒遮挡完整卡号和其他敏感信息，客服不要在回复中复述。

### 用户看到别人的数据
立即升级安全事件，不要只建议刷新页面。

## 15. 人工升级条件

- 用户提出正式隐私权请求；
- 涉及数据泄露或跨用户数据暴露；
- 用户无法完成敏感操作身份验证；
- 注销涉及未完成争议交易；
- 数据导出内容明显错误；
- 用户要求法律或监管层面的数据说明；
- 内部系统出现权限越权。

## 16. 常见问题

### 注销后订单记录会立刻消失吗？
不一定。与交易、财务、安全相关的必要记录可能需要在一定期限内保留。

### 客服能看到我的密码吗？
不能。系统不应向客服提供可读取的明文密码。

### 为什么导出数据还要再次验证？
数据导出属于敏感操作，额外验证可以降低账户被盗后数据被批量导出的风险。
